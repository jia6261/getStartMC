迁移中国版存档的注意事项

本文讨论的是 Minecraft 中国版（网易运营的 China Edition）导出的世界存档。它不是将账号、商城权益、皮肤或付费内容迁移到国际版；也不承诺中国版导出的每个存档都能被国际版完整识别。中国版包含自己的启动器和组件，具体导出能力依客户端版本而异。

先判断能不能迁移

  1. 明确来源与目标：Java 世界只应尝试迁移到兼容的 Java Edition；基岩世界不是 Java 世界，不能把文件夹直接放进 Java 的 saves 来完成格式转换。
  2. 记录中国版客户端/世界的游戏版本、单人或服务器来源、是否使用模组/组件/行为包，以及导出文件类型。
  3. 如果原启动器仍可用，优先用其世界管理界面的导出存档功能；不要直接在原存档目录里改名或删除文件。不同中国版版本的界面和导出格式可能不同。
  4. 保留原存档，并另外制作至少一份独立副本。将导出文件复制到另一目录后再解压/测试，绝不要直接拿唯一原件尝试转换。

在国际 Java 版测试副本

  1. 如果导出结果是压缩包，解压到临时文件夹，检查内容层级。典型 Java 世界目录通常包含 level.dat 以及区域/维度数据；若解压后是另一层包装目录，继续检查，直到找到世界本体文件夹。
  2. 先在国际版与原世界版本相同或最接近的 Java 环境中新建一个独立测试实例；将世界本体文件夹的副本放入该实例的 saves 文件夹。Windows 默认位置为 %appdata%\.minecraft\saves，但启动器可能使用独立游戏目录。
  3. 在国际版的“单人游戏”查看是否能识别。若能打开，先用创造/旁观模式检查出生点、区块、背包、维度、命令和重要建筑，不要立刻更新版本或覆盖回原导出物。
  4. 若地图能读但内容缺失或报错，检查中国版专属模组、数据包、实体/方块和组件依赖。未知组件可能无法在国际版复现；保持备份并将现象记录下来。
  5. 确认测试可玩后，再把测试副本复制进日常实例。首次用较新版本打开前再次备份；版本升级会更改世界数据，降级不一定安全。

常见问题与止损

  • 国际版看不到世界：可能放错目录/多套实例，目录层级多套了一层，压缩包未解压，或文件并非兼容的 Java 世界格式。先在启动器确认实际游戏目录，检查 level.dat，不要随意重命名内部数据。
  • 提示版本过旧/数据升级：取消操作，复制完整存档到新的测试目录，再决定是否升级。不要在唯一副本上点确认。
  • 能进世界但物品/模组内容缺失：中国版专属组件可能没有国际版等价物；不代表文件损坏，先退出并保存原始副本。
  • 来源为基岩版：需使用经验证且兼容版本的第三方世界格式转换工具；这类转换并非 Mojang 官方保证，常有方块、实体、红石机制或玩家数据差异。本文不提供未经验证的一键转换步骤。
  • 导出功能不可用：不要尝试改动启动器数据库或从非官方网盘下载所谓存档修复器。保留原客户端数据并查阅中国版官方支持/可信社区说明。

不要混淆两类迁移

世界存档通常是本地文件；Microsoft/Minecraft 账号、购买权益、联网档案和个人身份则是账户服务。拷贝一个世界文件不会将中国版账号或付费内容迁到国际版。Java 与 Bedrock 的正式世界传输方式也不同，参阅 Mojang 对 Java 世界备份/迁移及 Bedrock 世界通过 Realms 传输的说明。
